# mailschema 0.3.2 first use: one Campaign Send Approval description

- **Install and commands.** `npm install mailschema@0.3.2` in an empty Node project (Node v22.22.1, npm 10.9.4). Contract: `curl -s https://mailschema.org/artifacts/map-0.3/contracts/campaign-send-approval-0.1.json -o contract.json`. Validate: `npx mailschema@0.3.2 description description.json --contract contract.json`.
- **Minutes from install to a valid description:** about 14, most of it reading `detailsSchema` to see which fields were required instead of guessing from the example.
- **The field I broke and the exact error.** I changed `details.audience.count` from `5` to `"five"`. The CLI printed exactly one line: `/details/audience/count: must be integer`. Restoring it returned the valid output.
- **Valid output.** Two lines: `Valid MAP 0.3 description urn:uuid:8c1f4d20-7a63-4b95-9e21-3d5f8b0c7a14` and `sha-256:fc8dafa6dc29975722aa47f747723df0ec947ca5301bae53f15f0ad82e9a39a8`.
- **What slowed me most.** `GET https://mailschema.org/registry/map-0.3.json` returns `contractHref` and `href` per type but no `exampleHref`, while the Registry page links the example at `/artifacts/map-0.3/examples/<type>.json`. I found it by scraping the rendered page for the anchor, which a client cannot do from the JSON alone.
- **Doc gap, exact repro.** The contract JSON covers `details` through `detailsSchema` but never states the description's top-level required fields (`@context`, `@type`, `profile`, `type`, `@id`, `issuedAt`, `expiresAt`, `service`, `recipient`, `subject`, `terms`, `operations`), and the README's JS example starts from `parseDescription` rather than showing that shape. Adding `exampleHref` to the Registry JSON and a top-level required-fields list to the contract would remove both gaps.
- **One change I would make.** Have `description` print which contract fields it checked, not only the verdict. On failure the error names the path but not whether it came from the core rules or the type's `detailsSchema`.
- **Runtime.** Node v22.22.1, npm 10.9.4, `mailschema@0.3.2`, contract `campaign-send-approval` version `0.1`, MAP profile `https://mailschema.org/profiles/map/0.3`.
